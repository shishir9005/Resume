# The Projects Section

## Why projects matter for students
For students and internship applicants, projects are often the strongest evidence of skill. A good projects section can matter more than unrelated part-time work. Place Projects above Experience if your projects are more relevant to the target role than your jobs.

## What each project entry should include
Each entry needs: a clear project name, the tech stack, two to four bullets describing what you built and the result, and a link to the code or a live demo. Format example: "ATS Resume Scorer | Python, FastAPI, Streamlit, Supabase | github.com/user/repo". The first bullet should say what the project does and for whom; the following bullets should highlight technical decisions and outcomes.

## Show decisions and trade-offs
Interviewers care about why you made choices. Mention one meaningful engineering decision: "Switched the embedding model from PyTorch to ONNX runtime, cutting memory use by several hundred MB so the app fits on free hosting." This shows understanding rather than following a tutorial.

## Choosing which projects to include
Pick two or three projects that match the target role. A backend role wants APIs, databases, and deployment; an ML role wants data pipelines, training, and evaluation. Prefer one deployed, finished project over three half-finished tutorial clones. Course projects are fine if you describe your own contribution clearly.

## Common project mistakes
Listing only the tech stack with no outcome. Describing the tutorial instead of your own work. Broken or private GitHub links. Missing README in the repository. Using "we" throughout without saying what you personally did; use "I built" logic in bullets even in team projects.
