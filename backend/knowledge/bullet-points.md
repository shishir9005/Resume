# Writing Strong Bullet Points

## The action + task + result formula
A strong bullet answers three questions: what did you do, how did you do it, and what changed because of it. A useful template is "Accomplished [result] by doing [action] using [tools]", often called the XYZ formula. Example: "Reduced API response time by 40% by adding Redis caching to the product search endpoint." Weak version: "Responsible for improving API performance."

## Adding numbers and measurable results
Numbers make impact concrete and are easy for recruiters to scan. Useful metrics include percentages (latency cut by 30%), counts (500+ daily users, 12 REST endpoints), time saved (cut report generation from 2 hours to 5 minutes), scale (processed 1M rows), and quality (test coverage from 45% to 85%). If you do not know an exact number, use an honest estimate with "about" or "~", or describe scope instead (team size, number of features). Never invent numbers; interviewers will ask about them.

## Length and structure
Keep each bullet to one or two lines, roughly 12–25 words. Start with a strong past-tense action verb for past roles and present tense for current roles. Put the most impressive bullet first in each entry. Aim for 3–5 bullets per job and 2–4 per project.

## Before and after examples
Before: "Worked on the frontend of a web app." After: "Built 8 responsive React pages with TypeScript and Tailwind, cutting page load time by 35%."
Before: "Helped with data cleaning." After: "Cleaned and merged 3 datasets (120K rows) with Pandas, removing 9% duplicate records before model training."
Before: "Was responsible for testing." After: "Wrote 60 Pytest unit tests for the payment service, raising coverage from 50% to 82%."
