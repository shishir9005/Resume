# Common Resume Mistakes

## Spelling and consistency errors
Typos signal carelessness and can break keyword matching ("Pyhton" will not match "Python"). Check technology names for correct capitalization: JavaScript, PostgreSQL, GitHub, macOS. Keep tense, date format, and punctuation consistent across all entries.

## Duties instead of achievements
The most common weakness is describing what a role was supposed to do instead of what you did and changed. Every bullet should contain an action and, where possible, a result. See the bullet-writing guide for the action + task + result formula.

## Keyword stuffing and hidden text
Repeating keywords unnaturally or hiding white text in the document to trick an ATS is easy to detect and can get an application rejected. Use keywords naturally, inside real bullets.

## Unexplained acronyms and internal names
Write out a term the first time, or pair it with the common name: "Natural Language Processing (NLP)". Internal project codenames mean nothing to an outside reader; describe what the system does instead.

## Too much personal information
Leave out marital status, religion, full address, ID numbers, and unrelated hobbies unless the specific market expects them. Include links that work: test every LinkedIn, GitHub, and demo URL before applying.

## One resume for every job
Sending the identical resume to every posting lowers the match rate. Keep a master resume with everything, then make a tailored one-page copy per application.
