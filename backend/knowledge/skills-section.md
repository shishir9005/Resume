# The Skills Section

## Organize skills into groups
Group skills into short labeled lines so both an ATS and a recruiter can scan them: "Languages: Python, Java, SQL", "Frameworks: FastAPI, React, PyTorch", "Tools: Git, Docker, Linux, AWS". Avoid long unstructured lists and avoid skill bars or percentages, which are meaningless and do not parse.

## Only list skills you can back up
Every skill on the resume can become an interview question. List a skill only if you could explain how you used it. Separate proficiency honestly if needed, for example "Familiar with: Kubernetes". Remove outdated or trivial items such as "Microsoft Word" for technical roles.

## Skill validation: show evidence in projects and experience
A listed skill is much more convincing when the same skill appears in a project or job bullet. The ATS Resume Scorer measures this as Skill Validation: for each skill, it checks whether a project or experience entry mentions or semantically matches it. Unvalidated skills lower the score. To fix an unvalidated skill, either add a bullet that shows you using it ("Containerized the API with Docker and deployed it on a 1 GB VPS") or remove it from the list.

## Matching the job's wording
Use the same spelling and naming as the job description: if the posting says "PostgreSQL", do not only write "Postgres"; if it says "Machine Learning", include the full phrase as well as "ML". Including both the acronym and the full form, such as "Natural Language Processing (NLP)", helps keyword matching.

## Soft skills
Do not list soft skills like "teamwork" or "communication" as bare words; they carry no weight. Show them in bullets instead: "Coordinated a 4-person team using weekly sprints and GitHub Projects".
